# 语音提供商扩容与「自定义」全链路（2026-11-20）

> 用户原话：「语音的apikey输入你现在还是默认只有硅基流动和openai的。
> 我说的要适配市面上大部分的语音apikey呢，最好还要支持自定义的」

一句话结论：**从 2 家扩到 7 家，并把"自定义端点"做成一条真正能用的路** ——
用户填 BaseUrl + 模型名 + 音色 id，就能接上我们没收录的 OpenAI 兼容端点
（OneAPI / New-API / 自建网关 / 内网服务）。

---

## 1. 为什么不是"多加几个常量"

原来的设计假定"所有 TTS 厂商都长 OpenAI 的样子"：

```
POST {baseUrl}/audio/speech
body: {model, input, voice, response_format}
header: Authorization: Bearer <key>
```

这个假定对硅基流动、OpenAI、DeepInfra、阶跃、智谱都成立。收 ElevenLabs 时它塌了：

| 维度 | OpenAI 兼容 | ElevenLabs |
|---|---|---|
| 路径 | `/audio/speech` | `/v1/text-to-speech/{voice_id}`（**音色在路径里**） |
| 格式 | body 的 `response_format` | **query 的 `output_format`** |
| 字段名 | `input` / `model` | `text` / `model_id` |
| 鉴权头 | `Authorization: Bearer` | `xi-api-key` |

四个维度都不同。若继续用「多几个 if 塞字段」的办法，一定会在
"给 ElevenLabs 发了 `response_format`" 这类地方**安静地失效** ——
不报错、不合声、只是没声音。

所以把协议提成一个维度：`enum TtsProtocol { OPENAI, ELEVENLABS }`，
`buildRequest` 按它分派，**两个协议各自的请求体分开写**，共用同一组
"格式 / 模型 / 音色"解析函数（`effectiveFormat` / `resolveModel` / `resolveVoice`）。

⚠️ 这一条不是洁癖：`renderRequestBody`（测试用）与 `buildRequest`（真机用）
曾经各写一遍 JSON，加模型覆盖时就出现了"测试断言一处、真机发另一处"。
现在两者共用同一组解析函数。

### 2.1 Groq 为什么没进表

Groq（PlayAI）只输出 `flac / mp3 / ogg / wav`，**没有 PCM**。
而播放端 `TtsSpeaker` 是把响应字节**当裸 PCM 直接写进 AudioTrack** 的
（`24kHz / 16bit / 单声道`）。给它 mp3，出来的是把压缩字节当波形播放的噪声 ——
比没有声音更糟，而且用户完全无法理解发生了什么。

要收它必须先做设备侧解码（mp3 → PCM），那是独立一刀。
所以它被写进文件头「仍然刻意不收的」清单里，理由写在代码里，
而不是悄悄地少一个厂商。

同理不收：DashScope / 火山 / 腾讯 / 讯飞 / 百度（多字段签名凭据）、
MiniMax（JSON 套 hex 音频，破坏流式契约）、Fish（msgpack）、
OpenRouter（无语音）、本地 TTS（该走系统 `TextToSpeech`）。

### 2.2 智谱为什么声明了"没有 STREAM"

它的 `/audio/speech` 是整段返回的。声明 STREAM 会让上层按流式读 ——
读到的是"要等全部生成完才出声"。
测试里把这条钉成**显式例外**（`只有智谱不声明流式能力`），
而不是让断言从"人人流式"悄悄放宽成"随便"。

### 2.3 价格为什么有三家是空

智谱/阶跃的官方价目表按"万字符/元"标且随套餐浮动；ElevenLabs 是 credits 订阅制；
自定义端点我们连它按什么计费都不知道。
硬换算成"每百万字符美元价"会得出一个**看着精确、其实错**的数字，
而错的价格比没有价格更危险（预算熔断会据此做决定）。

`estimateCost` 对未知返回 `Cost(0.0)`，与对话侧同一条规则：
未知不等于免费，只等于"没得算"。测试里把这份例外清单**双向钉死**
（清单内必须为 null、清单外必须非 null），免得它慢慢变成"什么都允许"。

## 3. 「自定义」是怎么走通的

四层都要改，缺一层就断：

```
Key 编辑页（模型名 / 音色 id）
  → EditorState.model/.voice
  → CredentialRepository.add(modelOverride, voiceOverride)
  → CredentialEntity（DB v5 两个新列）
  → GatewayCredentialSource.resolve → ResolvedCredential
  → ProviderCredential.modelOverride/.voiceOverride
  → OpenAiCompatTtsProvider.resolveModel/resolveVoice
  → 请求体里的 model / voice（或路径里的 voice id）
```

### 3.1 为什么加在凭据上，而不单开一张表

这两个值**跟着 Key 走**：换一个 Key 通常也换一个模型名。
单开一张表会多出一个悬空状态（"有条件、没 Key"或反过来），
而那个状态没有任何界面能表达。

### 3.2 为什么"自定义"必须填地址

它的 `defaultBaseUrl` 是**空串**，我们刻意不给假默认值。
不填就存进去的话，用户每次合成都是"连不上"，而界面上一切正常 ——
他只会觉得"这个 App 的语音坏了"。
所以在 `CredentialRepository.add` 里就拦住，并说清缺哪一步。

实现上靠 `TtsProvider.requiresCustomEndpoint`（接口默认 false，
自定义项覆写为 true），**不靠 `if (providerId == "custom-tts")`** ——
后者会让仓储层依赖一个字符串常量。

### 3.3 空串 vs null

`null` = 用默认值；空串会被原样发出去 → 上游报"参数缺失"，
而用户明明已经配完了。所以三处都做 `?.trim()?.takeIf { it.isNotEmpty() }`：
UI 保存时、仓储入库时、Provider 解析时。
测试里有一条专门钉这个（`空白的覆盖值按没填处理_不会发出空 model`）。

## 4. 格式降级：为什么优先降到 PCM

`effectiveFormat(requested)`：

1. 请求的格式在 `supportedFormats` 里 → 用它；
2. 否则 PCM 在清单里 → 降 PCM；
3. 否则退清单第一项。

**优先 PCM** 是因为播放端只吃 PCM。降到 mp3 的话
`TtsSpeaker` 会把压缩字节当 PCM 写进 AudioTrack —— 一片噪声。
若某个 profile 连 PCM 都没有（目前没有），`synthesize` 会抛
`ProviderException.ProtocolError`，日志里带厂商名和"只接受 PCM"。

## 6. 已知局限

1. **`listVoices()` 恒返回 null**：OpenAI 兼容协议没有枚举端点，
   音色只能靠 profile 清单 + 用户手填。阶跃只列了 1 个音色就是这条的直接后果。
2. **没有设备侧解码**：只给压缩格式的厂商一律进不来（见 §2.1）。
3. **多字段签名的厂商（阿里/火山/腾讯/讯飞/百度）进不来**：凭据模型目前是
   "一个 Key"，它们要 AppKey + AccessKey + Secret。
4. **自定义项的 `maxCharacters` 是 null**（不限长）：我们无法知道对方的上限，
   编一个数字会让用户在没超限时被拦。
