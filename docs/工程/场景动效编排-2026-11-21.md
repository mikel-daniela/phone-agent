# 场景动效编排 · Choreography

> 2026-11-21 · 针对 PocketAgent 的界面动效设计
> 前置文档：`UI与动效优化方案-2026-11-02.md`（修 bug 清单）、`UI设计评审-2026-11-02.md`（视觉规范）
> 本文不重复它们的内容。它们解决「哪里不对」，本文解决**「合起来不像一个东西」**。

---

## 0. 一句话

**动效的单位不是组件，是场景。**

一个按钮的 `scale 0.92` 做得再准，和它旁边那个气泡的淡入、那条进度线的生长、那个徽章的滑入之间没有关系，用户看到的就不是一个产品，是四段各自正确的小动画。

所以这次不设计"按钮怎么按"，设计**"一次发送"、"一次落定"、"一次接管"**长什么样。

---

## 1. 为什么需要这一层

现有代码里的动画是**逐处实现**的：`AgentCard` 里有 `animateContentSize`、`RunningIndicator` 自己呼吸、`CallMotion` 用 `when` 硬切三套 Canvas、`TasksScreen` 的滚动各自 `animateScrollToItem`。

每一处拆开看都没错，问题出在**它们之间**：

| 症状 | 现场 | 本质 |
|---|---|---|
| 打电话时"闪一下" | `CallMotion` 按 `phase` 直接 `when` 换 Canvas，整组画布瞬间换掉 | 三态之间**没有过渡**，只有替换 |
| 消息发出去时文字"凭空消失" | 输入框清空与气泡出现各自 `LaunchedEffect`，谁先谁后看重组顺序 | **没有因果顺序**，只有巧合 |
| 卡片出现时标题被挤动一下 | 徽章从无到有参与布局 | 动效需求**反过来要求 UI 结构**（见 §8） |
| 从后台切回来，进度条从头跑 | 进度存在 `remember` 里 | 系统重建时**重播了进场** |
| "感觉有点慢"但说不出哪慢 | 单看每一段都 ≤300ms，加起来一条链 1.2s | **没有总时长预算** |

这五条都不是"某个动画参数没调好"，是**缺一层编排**。

## 2. 六条不变量

编排层的全部价值，是把"感觉"变成可以被测试钉住的六条断言。写成测试后，任何人改数字都会被拦。

| # | 不变量 | 人话 | 违反时的症状 | 测试 |
|---|---|---|---|---|
| **R1** | 一口气 | 一个场景里，**零点起跑的主体**最多一个 | 两个东西同时启动，眼睛不知道看谁 | `只有一个主体在零点起跑` |
| **R2** | 一块石头 | 一个场景里，`STONE` 级最多一段 | 全是重家伙，整屏在砸 | `石头不超过一段` |
| **R3** | 有头有尾 | 任何场景总时长 ≤ **640ms** | 用户开始等动画 | `场景不超过上限` |
| **R4** | 不许晃 | 终点过冲 ≤ **3%** | 弹性过头 = 廉价 | `过冲不超过 3%` |
| **R5** | 归位不重播 | 恢复场景 `duration = 0` | "它刚开始跑"（其实一直在跑） | `归位不重播` |
| **R6** | 打断要快 | 收尾 ≤ **80ms**，且快于任何进场 | 想停停不下来 | `打断快于进场` |

**R1 的"主体"不是"图层"。** 这是实现时踩出来的：`STREAM_LINE` 的正字和笔尖是两个 `Target`，但它们是**同一条线**，必须同一刻起跑。所以 `Step` 里有 `subject` 字段，判重按 `subject`，不按 `target`。三个呼吸环、九根波形条同理——九根条是"一个波形"，不是九个东西。

```kotlin
data class Step(
    val target: Target,          // 画在哪个元素上
    val subject: Target = target, // 属于哪个"主体"（R1 判重用它）
    ...
)
```

**R3 是硬上限，不是平均值。** 640ms 的来源：一次操作后用户愿意"看"而不动手的窗口约 0.6–1s；超过 1s 就开始怀疑卡了。640 留了 360ms 余量给系统启动和网络。

## 3. 质量模型：羽毛 / 纸 / 石头

不按"快慢"分，按**重量**分——重量同时决定时长和过冲，不决定曲线（见 §4）。

| 质量 | 时长 | 过冲 | 隐喻 | 用在哪 | **不**用在哪 |
|---|---|---|---|---|---|
| `FEATHER` 羽毛 | 120–200ms | 0 | 光、字、图标、粒子 | 淡入、图标缩放、笔尖、徽章出现 | 任何"实体"位移 |
| `PAPER` 纸 | 240–300ms | ≤2% | 卡片、气泡、输入框 | 位移、展开、压实 | 呼吸/循环动画 |
| `STONE` 石头 | 300–520ms | ≤3% | 抽屉、接管条、波形站起 | 一次场景里最重的那一个 | 连续两次出现 |

**为什么只有三档**：超过三档，设计时要在"这个算纸还是算厚的纸"上耗时间，而用户看不出差别。三档足够覆盖"轻—中—重"，且每档都有明确的不允许项。

**石头的稀缺性是设计的一部分。** R2 限制"一个场景最多一块石头"，是因为石头的作用是**给这一屏定调**——一屏里两块石头，等于没有重点。

## 4. 曲线铁律

### 4.1 曲线管形状，质量管时长与过冲

这是本设计里代价最大的一个修正。第一版写成"纸 = `SETTLE`（`EMPHASIZED_DECELERATE`）"，结果 8dp 的落下变成：

```
t=0    ──┐            ← 第一帧就到 4dp（走完 48%）
          │
          └──────────  剩下 20 帧蹭完另外 4dp
```

`EMPHASIZED_DECELERATE = (0.05, 0.7, 0.1, 1)` 在**前 5.7% 时间**里走完 **48% 距离**。位移上用这条曲线，就是 `Motion.kt` 注释里点名的"唰一下到位再原地磨 200ms"——比线性还难看。

**修正后的规则：曲线只认轴。**

| 轴 | 曲线 | 理由 |
|---|---|---|
| `EXTENT`（进度/高度/裁切） | `LINEAR` | 生长的东西匀速最诚实；带缓动像"卡了一下" |
| `ALPHA`（透明度） | `EMPHASIZED` | 人眼对淡入的加速不敏感，缓出更"自然" |
| `SCALE`（缩放） | `FEATHER`? `EMPHASIZED` : `SETTLE` | 缩小用加速（收得干脆），放大用减速（站稳） |
| `X` / `Y`（位移） | **一律 `STANDARD`** | 位移必须"起步就有速度、到位就停" |

**质量只改两个数字：时长、过冲。** 调"这张卡片重一点"，只动 `durationMs` 和 `settle`，不会顺手把落点曲线也换掉——这是分层的意义。

### 4.2 过冲只作用于位置，不作用于透明度和裁切

```kotlin
val placed = withSettle(eased, settle)   // → dx / dy / scale
val flat   = eased                        // → alpha / extent
```

透明度冲到 1.01 再回来看不见任何东西；extent 会被 `clipRect` 裁在 1，等于"提前一点到"。两者都是白算。

### 4.3 过冲的实现（第一版写错过）

```kotlin
// 错：峰值恒为 0，永远不越终点
progress = eased + settle * sin(PI * eased)

// 对：前 75% 冲到位+settle，后 25% 回落，落点严格 = 1
up   = (eased / 0.75).coerceIn(0f, 1f)
down = ((eased - 0.75) / 0.25).coerceIn(0f, 1f)
progress = (1 + settle) * up - settle * down
```

"过冲"的定义是**超过 1**。第一版"峰值恒为 0"是数学错误，不是参数问题。`ARRIVAL_AT = 0.75` 保证落点严格等于 1（不然末帧会歪 3%）。

## 5. 十四个场景

`at/dur` 单位 ms。质量后面跟的是轴。**"为什么"这一列是这份文档的主体**——数字可以调，理由不能丢。

### 5.1 启动

| 场景 | 元素 | at/dur | 质量·轴 | 参数 |
|---|---|---|---|---|
| `COLD_START` 640 | `HEADLINE` | 120/520 | 羽毛·α | `riseDp=-12` |
| | `COMPOSER` | 260/280 | 纸·y | `riseDp=8` |
| | `SEND_ICON` | 420/160 | 羽毛·scale | `fromScale=0.90, fromAlpha=0.6` |

**为什么**：系统冷启动有约 300ms 的白屏余量，底色第一帧就在，所以观感是"从空到有人"，不是"从无到有"。开场白用 520ms 是**故意慢**——它在被读，不是在被扫。发送箭头最后才出现，否则用户会以为"现在就能按了"而按在一个还在淡入的按钮上。
**为什么上来就 -12dp**：从下往上浮是"内容升起来"，从上往下掉是"东西砸下来"，首屏要后者之外的东西。

### 5.2 发送

| 场景 | 元素 | at/dur | 质量·轴 | 参数 |
|---|---|---|---|---|
| `SEND` 360 | `USER_BUBBLE` | 20/280 | 纸·scale+y | `fromScale=0.72, riseDp=8` |
| | `COMPOSER` | 40/260 | 纸·extent | — |
| | `SEND_ICON` | 0/120 | 羽毛·scale | `fromScale=0.86` |
| | `MESSAGE_LIST` | 60/300 | 纸·y | — |

**为什么气泡先动、输入框后塌**：文字**离开**输入框，变成上面的气泡。因果上"结果"（气泡出现）必须早于"容器复位"（输入框收回）。反过来会有一帧"文字凭空消失"，那是用户唯一可能怀疑"没发出去"的瞬间——而这一瞬间的怀疑会让他再点一次发送。
**为什么气泡从 0.72 起不是 0**：0 是"弹窗从无到有"，0.72 是"东西从手里飞出去"。这是同一个动作的两种读法，选错就把聊天读成了通知。

### 5.3 思考

| 场景 | 元素 | at/dur | 质量·轴 | 参数 |
|---|---|---|---|---|
| `AWAIT_FIRST_TOKEN` 200 | `THINK_DOTS` | 0/200 | 羽毛·α | `fromScale=0.94` |

**为什么不用 `CircularProgressIndicator`**：转圈是"机器在忙"，三个点呼吸是"人在想"。用户在等一句人话，不是在等一个任务完成。这一个选择决定了整个产品是"工具"还是"助理"。

### 5.4 流式输出（最高频）

| 场景 | 元素 | at/dur | 质量·轴 | 参数 |
|---|---|---|---|---|
| `STREAM_LINE` 360 | `STREAM_LINE` | 0/180 | 羽毛·y | `riseDp=6` |
| | `PEN_TIP` | 0/120 | 羽毛·α | `fromAlpha=0.55`，`subject=STREAM_LINE` |
| | `PARA_GAP` | 40/320 | 纸·extent | — |

**为什么这是最克制的一个**：它是全产品出现频率最高的动画——一段回答里会跑十几次。高频动画的目标**不是好看，是不被看见**。所以：
- 只浮 6dp，比标准的 8dp 更小（8dp 在十几次重复后会变成"文字在一跳一跳"）；
- **已经稳定的行完全不动**（只对新行做，旧行不留任何动画）；
- 8dp 的段间留白是唯一刻意让人**感到停顿**的地方——它对应模型真的在想下一段。停顿是信息，不该被抹平。

### 5.5 卡片四态

| 场景 | 元素 | at/dur | 质量·轴 | 参数 |
|---|---|---|---|---|
| `CARD_ENTER` 360 | `CARD_SPINE` | 0/180 | 羽毛·extent | — |
| | `CARD` | 40/280 | 纸·y | `riseDp=12` |
| | `CARD_BODY` | 120/240 | 羽毛·α | — |
| | `CARD_BADGE` | 180/160 | 羽毛·x | `slideDp=-8` |
| `CARD_COMMIT` 600 | `CARD` | 0/120 | 纸·scale | `fromScale=1.004` |
| | `CARD_BADGE` | 60/160 | 羽毛·α | — |
| | `CARD_PROGRESS` | 120/480 | 石头·extent | — |
| `CARD_LAND` 540 | `CARD_PROGRESS` | 0/240 | 羽毛·extent | — |
| | `CARD_BADGE` | 40/160 | 纸·x | `slideDp=-8, settle=0.03` |
| | `CARD` | 80/260 | 纸·scale | `fromScale=0.998, settle=0.02` |
| `CARD_FAIL` 520 | `CARD` | 0/40 | 羽毛·y | **`toRiseDp=1.5`**（向下砸） |
| | `CARD` | 40/240 | 纸·y | `riseDp=1.5`，**必须 `fromAlpha=1`** |
| | `CARD_BADGE` | 80/160 | 羽毛·α | — |
| | `CARD_EXITS` | 120/200 | 羽毛·α+y | `riseDp=4` |

**`CARD_ENTER` 的母题是"竖脊先出现"**：像笔先落下再写字。本体晚 40ms 才把它包进去，观感是"这条记录先有了骨架，再长出内容"。徽章最后——人先读"它要做什么"，再读"它现在什么状态"。

**`CARD_COMMIT` 用 1.004 的**收窄**不是放大**：1.004 是"握紧"，表示"要动手了"；放大成 1.02 读起来是"膨胀/炫耀"，完全相反。进度线**不表示进度**——它匀速、不回收、不对齐真实百分比，只表示"这只手正在动"。到 `CARD_LAND` 才收。

**`CARD_LAND` 的顺序是"先收线，再盖章，最后压实"**：线先收回（收尾），徽章滑出并带最大过冲（盖章=落定），本体压 0.2%（压实=放到桌上）。**没有任何庆祝动画**——它不是完成任务，是同事把东西放回你桌上。

**`CARD_FAIL` 是唯一有"撞"的场景**：40ms 的向下 1.5dp，几乎无缓动（瞬时），然后 240ms 弹回归位。撞击必须短到像"顿了一下"，长了就变成"摔"。出口按钮**一个一个出现**（120/200 起，各自 40ms 错开）——失败时刻用户是懵的，一次甩三个按钮他只会乱点。

### 5.6 通话三态（本设计唯一的"形变"）

| 场景 | 元素 | at/dur | 质量·轴 | 参数 |
|---|---|---|---|---|
| `CALL_LISTEN_TO_THINK` 420 | `CALL_RING` | 0/240 | 石头·scale | **`toScale=0.15`** |
| | `CALL_DOTS` | 240/180 | 羽毛·scale | `fromScale=0.40, settle=0.03` |
| `CALL_THINK_TO_SPEAK` 450 | `CALL_DOTS` | 0/180 | 羽毛·scale | **`toScale=0.30`** |
| | `CALL_BARS` | 180/270 | 石头·extent | — |
| `CALL_SPEAK_TO_LISTEN` 440 | `CALL_BARS` | 0/60 | 羽毛·extent | **`fromExtent=1, toExtent=0`** |
| | `CALL_RIPPLE` | 40/240 | 石头·extent | — |
| | `CALL_RING` | 240/200 | 羽毛·α | — |

**现状的问题**：`CallMotion` 用 `when (phase)` 直接换 Canvas，整组画布瞬间替换——打电话中途"闪"一下，像信号断了。这不是参数问题，是**没有过渡的对象**。

**解法是形变不是替换**：听 → 想，三圈呼吸环收拢成核（`toScale=0.15`，**留核不是归零**），三个点再从核里长出来（`fromScale=0.40`）。想 → 说，三个点塌进中心（`toScale=0.30`），波形从中心向两边**依次站起**（`EXTENT` 从左往右，隐喻"凝聚成声音"；回声才是向外扩散）。

**说 → 听必须"塌陷"不是"淡出"**：60ms 内 9 根条从满高收到 0。声音是被掐断的，没有渐弱过程。用淡出会让人以为"它还在说，只是变小声了"——这是通话里最糟的一种误解。

### 5.7 抽屉与归位

| 场景 | 元素 | at/dur | 质量·轴 | 参数 |
|---|---|---|---|---|
| `DRAWER_OPEN` 300 | `DRAWER_PANEL` | 0/300 | 石头·x | `slideDp=-320` |
| | `DRAWER_ITEM` | 80/200 | 羽毛·y | `riseDp=6` |
| `RESUME_ATTACH` **0** | `RESUME_MARK` | 0/**0** | 羽毛·α | — |

**抽屉本体由 `ModalNavigationDrawer` 驱动**，这里只编排"打开之后"的事：条目 30ms 步长错开，封顶 180ms（5 条以上不再加，否则最后一条要等半秒）。
**当前页不做 0.9 缩放**：项目里已经有玻璃 + 极光两层半透明，再叠一层缩放会露出渐变的断层。想法对，但和现有视觉层冲突——记在这里，等极光层重构后再考虑。

**`RESUME_ATTACH` 是全设计唯一 `duration = 0` 的场景**。从后台切回来**不能重播进场**——重播等于告诉用户"它刚开始"，而事实是"它一直在跑"。只做一次位置对位（进度线瞬间贴到真实值）。
**这也是一个代码约束**：进度必须存在 ViewModel 里，不能存 `remember`，否则系统重建时它就是 0，重播无法避免。

## 6. 打断策略

三个场景不是"进场"而是"收场"，它们决定了整套动效是否可信。

| 策略 | 用在哪 | 做什么 | 为什么 |
|---|---|---|---|
| `CANCEL` | 发送后立刻撤回、卡片被取代 | 直接跳到终态，`duration=0` | 用户已经不想看了，别让他看完 |
| `FREEZE` | 滑走/切页 | 停在当前姿态，回来继续 | 重播=世界重启，冻结=暂停 |
| `CONTINUE` | 网络慢、模型还在写 | 保持，不重启 | 重启会让"正在打字"变成"又从头发呆" |

**R6 要求打断 ≤80ms 且快于任何进场**：进场最快 120ms（羽毛），收场必须更快。一个场景如果"想停停不下来"，它就从"提供信息"变成"扣留时间"。

## 7. 降级

两个开关，都在 `Choreography.scene()` 里处理，**不在 UI 层各写一遍**。

| 开关 | 触发 | 行为 | 实现 |
|---|---|---|---|
| 关动画 | `Settings.Global.ANIMATOR_DURATION_SCALE == 0` 或 `TRANSITION_ANIMATION_SCALE == 0` | 返回**空场景**（`static=true, totalMs=0`） | 不是把时长设成 1ms——那仍会跑一帧，屏幕上会闪 |
| 省电 | `PowerManager.isPowerSaveMode` | 位移/缩放/过冲全部归零，**只留 alpha** | 淡入几乎不耗电（不触发布局、不重绘几何），位移和缩放要每帧重画 |

读取用 `MotionPreference.read(context)`，注意是 `Settings.Global` 不是 `Settings.System`（读错恒返回 1f 且不报错）。`LocalMotionPreference` 是 `staticCompositionLocalOf`（变化极少），`rememberMotionPreference()` 注册三个 ContentObserver 持续监听。

**降级的曲线表由 Kotlin 预计算，不在 JS / 不在 Compose 里重实现**：`ChoreoDemo.json()` 里每个 target 同时给 `k`（正常）和 `kEco`（省电）两份采样，两者都来自同一个 `Choreography.scene()`。这样"省电模式长什么样"和真机是同一份数据，不会漂移。

## 8. 动效对 UI 的三条硬要求

这一节是**反向输出**：为了让编排成立，UI 结构必须满足三个条件。改 UI 时要守住，否则动效会退化成"闪"。

1. **卡片必须有独立的 spine 层。**
   `CARD_ENTER` 的母题是"竖脊先出现"。如果边框只是 `Modifier.border`，它没有自己的绘制时机，只能跟着卡片本体一起出现——母题就没了。需要一条独立的 `Canvas`/`Box` 画左边那条竖线，才能单独做 `extent`。

2. **徽章必须在布局里 alpha=0 占位，不能条件渲染。**
   现在 `RUNNING` 时徽章位换成 `RunningIndicator`，状态改变时布局宽度变化 → 标题被挤动一下。必须**永远占位**、只改 `alpha` 与 `contentDescription`。这一条同时解决了无障碍：读屏软件朗读的状态文字不能忽隐忽现。

3. **输入框塌陷必须用 `scale`，不能改高度。**
   `COMPOSER` 的 `EXTENT` 只能做成"裁切"，不能真的 `height = 0`。改高度会触发整列重新布局，气泡正在飞的那一帧会被打断——这是 `animateContentSize` 类实现最容易翻车的地方。正确做法：内容不动，外面套一层 `clipRect(right = width * extent)`。

## 9. 代码结构

四层，**依赖方向单向**，越往下越可测。

| 文件 | 行数 | 职责 | 依赖 |
|---|---|---|---|
| `android/agentui/.../Choreography.kt` | 827 | 编排表：14 个场景的 `Step` 数据 + `curveFor` + 降级 | 无（纯 Kotlin） |
| `android/agentui/.../Playback.kt` | ~300 | 求值器：贝塞尔反解、过冲、`poseOf`、`frameOf`、`toJson` | `MaterialMotion`（纯数学） |
| `android/app/.../ui/design/Choreographed.kt` | ~180 | 渲染：单时钟 `Animatable` → `graphicsLayer` | Compose |
| `android/agentui/.../ChoreoDemo.kt` + `resources/choreo-demo/template.html` | ~120 + 700 | 分镜台：把同一份数据喂给 HTML 演示 | 无 |

**为什么渲染层极薄**（文件头注释写着"这里出现任何数字（除 0f/1f）都是 bug"）：所有"多少毫秒、浮几 dp、什么曲线"都在 `agentui` 里，Compose 只负责**把已经算好的姿态画出来**。这样 90% 的设计可以被 JVM 单测覆盖，不需要真机。

**为什么只能有一个时钟**：`ChoreoClock` 内部是一个 `Animatable<Float>` 从 0 推到 1，用 `LinearEasing` 推进**时间本身**，曲线由 `Playback` 按元素施加。如果用 N 个 `Animatable`（每个元素一个）：
- 相位漂移：N 个动画各自有几毫秒误差，气泡和输入框就不同步了；
- 无法打断：停下来要说 N 次；
- 状态跃迁重影：新旧两套同时存在时，同一元素有两个动画器。

一个时钟 + 纯函数求值，天然没有这三个问题。

```kotlin
val clock = rememberChoreo(Beat.SEND)      // 读 LocalMotionPreference，自动降级
Modifier.choreo(clock, Target.USER_BUBBLE)  // 只写 graphicsLayer 的 alpha/x/y/scale
```

**只用 `graphicsLayer`，不用 `offset`/`size`**：前者是渲染期变换（不触发布局），后者会。`NavHost` 的转场（`slideInHorizontally`）恰恰是后者——这也是为什么"整屏 push 会卡"（见 §11）。

1. dp→px 必须换算（340px 画布代表 393dp 屏，系数 0.8651），否则幅度虚高 16%；

## 附：一句话总结每一处为什么这么做

- **气泡先动、输入框后塌** —— 让"发出去了"这件事在物理上成立。
- **思考用三个点不用转圈** —— 等的是人，不是任务。
- **流式输出只浮 6dp** —— 它会出现十几次，克制是唯一正确的选择。
- **卡片竖脊先出现** —— 先有骨架再长肉，这是"记录诞生"而不是"卡片弹出"。
- **落定没有庆祝** —— 它是同事把东西放回桌上。
- **通话三态是形变不是替换** —— 打电话途中的"闪"会被读成信号断了。
- **说 → 听是塌陷不是淡出** —— 声音是被掐断的。
- **归位零时长** —— 它一直在跑。
- **打断 80ms 以内** —— 想停停不下来，动效就从"给信息"变成"扣时间"。
